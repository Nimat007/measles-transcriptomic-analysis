# 03 — Single-Cell Clustering, Substructure Analysis, and Annotation

## 1. Overview

This work package investigates the cellular structure of the integrated single-cell RNA-sequencing dataset used in the Measles Virus (MeV) host-response project.

Building on the quality-control and integration workflow, this stage performs graph-based clustering, compares clustering resolutions, evaluates cluster composition across sequencing libraries, examines selected cluster substructures, and assigns provisional biological labels using gene-level marker evidence.

The goal is to characterize the epithelial cell populations represented in the dataset while documenting ambiguity and avoiding unsupported cell-type assignments.

## 2. Input Data

- **Dataset:** GSE168775
- **Data type:** Single-cell RNA sequencing
- **Primary input object:** `GSE168775_Integrated_Benchmarked.rds`
- **Input format:** Seurat object generated by the preceding QC and integration workflow
- **Configuration:** `config.yml`, which defines clustering and annotation parameters

The input object contains the cell-level expression data, metadata, and dimensionality-reduction representations required for clustering and downstream interpretation.

## 3. Analysis Workflow

### Step 1 — Validate the integrated representation

The clustering workflow loads the benchmarked Seurat object and verifies that the configured dimensionality-reduction representation exists, has one embedding row per cell, and contains no missing embedding values.

The clustering parameters and random seed are read from the project configuration to make the analysis settings explicit.

### Step 2 — Construct the nearest-neighbor graph

A nearest-neighbor and shared-nearest-neighbor graph is constructed using the configured dimensionality reduction, number of dimensions, and neighborhood size.

Explicit graph names are used to distinguish the intended clustering graph from other graph objects that may exist in the Seurat object.

### Step 3 — Perform multi-resolution clustering

Graph-based clustering is run at the configured primary resolution and additional sensitivity resolutions.

The primary resolution is stored as the active cluster identity, while alternative resolutions are retained for comparison. This allows the analysis to examine whether broad cluster structure persists or changes when clustering granularity is altered.

### Step 4 — Audit cluster composition

Cluster composition is summarized using total cell counts, percentages, condition composition, and the number of contributing sequencing libraries.

Additional tables describe:

- Cluster-by-library proportions.
- Library-by-cluster proportions.
- Raw cell counts for each library and cluster.
- Cell counts stratified by cluster, sampling day, and experimental condition.

These summaries help identify clusters with limited representation across libraries or uneven distributions across experimental groups. They are descriptive diagnostics and do not, by themselves, establish that a cluster is biologically valid.

### Step 5 — Assess clustering-resolution sensitivity

Correspondence tables compare the primary clustering resolution with lower and higher resolutions.

Maximum-overlap summaries and cluster-resolution tracking are used to investigate whether clusters remain recognizable, split into smaller populations, or merge into broader groups as resolution changes.

Marker-program granularity audits examine selected epithelial programs, including basal, secretory, ciliated, mucous, deuterosomal, and cycling-associated markers.

These analyses are exploratory aids for deciding how much biological interpretation the observed clustering structure can support.

### Step 6 — Investigate selected cluster substructures

Targeted substructure diagnostics examine selected parent clusters and their finer-resolution daughter clusters.

The workflow summarizes daughter-cluster sizes, library composition, and the distribution of cells across libraries. It also performs exploratory daughter-cluster marker comparisons and examines selected canonical marker programs.

A practical cell-count screen is used to distinguish larger daughter populations from small fragments for interpretation. This is a pragmatic screening rule, not a formal statistical validity threshold.

### Step 7 — Apply provisional biological annotations

A predefined annotation dictionary maps the primary clusters to two levels of labels:

- **Broad lineage:** a conservative classification such as Basal, Secretory, Ciliated, or Unresolved.
- **High-resolution state:** a more specific descriptive label for selected cluster-associated transcriptional states.

Integrity checks ensure that cluster identifiers are represented in the annotation dictionary and that the mapping does not produce missing annotation values.

Annotated UMAP plots are generated to visualize the broad lineage and high-resolution state assignments.

### Step 8 — Correct annotations using marker evidence

A subsequent annotation-correction step revises broad-lineage assignments using the specified cluster-to-lineage mapping informed by the gene-level marker audit.

Clusters that cannot be assigned confidently to a broad epithelial lineage remain Unresolved rather than being forced into a specific cell-type category.

The corrected object is saved separately from the provisional annotated object, preserving the distinction between the initial and corrected annotation stages.

## 5. Main Outputs

The scripts are configured to produce several types of outputs:

- Cluster composition and condition-distribution tables.
- Library-by-cluster cell counts and proportions.
- Clustering-resolution correspondence and overlap summaries.
- Marker-program granularity and targeted substructure diagnostic tables.
- Daughter-cluster composition and marker-comparison results.
- A cluster annotation dictionary and report of unresolved clusters.
- UMAP visualizations of broad lineages and high-resolution states.
- Provisional clustered and annotated Seurat objects, followed by a corrected annotated object.

Exact filenames and output locations are defined by the individual scripts and project configuration. Only outputs that have actually been generated and checked should be presented as completed results.

## 6. Methodological Considerations

- **Resolution sensitivity:** Cluster assignments can depend on graph and resolution parameters. Comparisons across resolutions are used to assess structural stability rather than assuming a single resolution is uniquely correct.
- **Library composition:** A cluster dominated by one sequencing library may reflect biological composition, technical effects, or both. Library-distribution tables are descriptive checks, not proof of technical or biological origin.
- **Marker-based interpretation:** Cluster labels are working biological interpretations informed by marker patterns, not definitive experimental validation of cell identity.
- **Unresolved populations:** Ambiguous clusters are retained as unresolved when the available evidence does not support a confident broad-lineage assignment.
- **Substructure interpretation:** Small daughter clusters require particular caution because their apparent separation may reflect limited cell numbers or unstable clustering.
- **Annotation versioning:** Provisional and corrected annotation objects are distinguished so that changes in the interpretation can be traced.

## 7. Relationship to the Overall Thesis

This work package translates the integrated single-cell representation into interpretable cellular groups and documents the robustness and uncertainty of those groupings.

The resulting cluster identities and annotations provide inputs for subsequent pseudobulk eligibility assessment, contrast-specific analysis, and cross-dataset comparison. Downstream analyses should account for cluster composition and the number of cells contributed by each biological sample or sequencing library.

## 8. Reproducibility and Status

The workflow is implemented in R using Seurat and supporting packages. Reproduction requires the integrated Seurat input object, the project configuration, compatible package versions, and the required source data from the preceding workflow.

Large intermediate Seurat objects do not need to be committed to the public repository if their size or data-sharing restrictions make that impractical. Instead, document how they are generated and which preceding script produces each required input.

**Status:** Computational clustering, diagnostic, and annotation workflow. Final biological interpretations should be supported by the documented marker evidence, cluster-composition diagnostics, and subsequent analyses.
